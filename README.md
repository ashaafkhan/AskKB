# AskKB - Ask your Knowledge Base

AskKB is a notebook-based, source-grounded AI research assistant. Users create **Notebooks** (isolated workspaces), populate each with heterogeneous **Sources** (PDFs, plain text, websites, YouTube videos, transcripts), and ask questions that are answered strictly from the content of those sources. The core promise of AskKB is absolute provenance: every single answer generated by the LLM is backed by an inline, clickable citation that jumps you to the exact highlighted location in the original document or video timestamp.

## Architecture

AskKB uses a modern decoupled architecture:

*   **Frontend:** Next.js (React), Tailwind CSS.
*   **Backend:** Node.js with Express and TypeScript.
*   **Metadata DB:** PostgreSQL via Prisma (Stores Notebooks, Sources, Chat History, Chunks metadata).
*   **Vector DB:** Qdrant (Stores Chunk Embeddings for fast semantic search).
*   **Embedding Model:** Google Gemini (`text-embedding-004`).
*   **Chat LLM:** Groq (`llama3-8b-8192`) for ultra-fast, streaming completions.
*   **Bonus Features:** Google Cloud Text-to-Speech for Podcast generation.

## Setup Instructions

1.  **Clone and Install**
    ```bash
    git clone https://github.com/ashaafkhan/AskKB.git
    cd AskKB
    
    # Install backend dependencies
    cd backend
    npm install
    
    # Install frontend dependencies
    cd ../frontend
    npm install
    ```

2.  **Environment Variables**
    Copy `.env.example` to `.env` in the root folder, and fill in the values (see the table below).

3.  **Database & Vector Store Setup**
    Ensure you have a PostgreSQL instance and a Qdrant instance running locally (e.g., via Docker).
    ```bash
    # Apply Prisma migrations
    cd backend
    npx prisma db push
    ```

4.  **Run the Servers**
    ```bash
    # In the backend folder:
    npm run dev
    
    # In another terminal, in the frontend folder:
    npm run dev
    ```

## Retrieval Flow Explanation

1.  **Ingestion & Chunking**: When a source is uploaded, its text is extracted (e.g., transcript fetched, PDF parsed). The text is chunked recursively aiming for ~500-token blocks with a slight overlap.
2.  **Embedding**: Each chunk is embedded using the `text-embedding-004` model from Gemini. The vectors are upserted into Qdrant, rigidly tagged with `notebook_id`, `source_id`, and `chunk_id`.
3.  **Search**: When a user asks a question, the query is embedded, and a vector search is performed in Qdrant *strictly filtered* by the current `notebook_id` to guarantee isolation. The top 5 matching chunks are retrieved.
4.  **Generation**: The chunks are formatted into a system prompt. The Groq LLM is instructed to answer strictly based on the context and to output citations in a specific format (`[Document X | Source ID: Y]`). The response is streamed to the frontend via Server-Sent Events (SSE).

## Known Limitations

-   **Web Scraping**: JS-heavy Single Page Applications might not extract cleanly since we use a basic readability fetcher instead of a headless browser.
-   **PDF Highlighting**: When clicking a PDF citation, we only display the raw extracted text in the Source Viewer, rather than rendering the actual PDF with bounding box highlights.
-   **Audio Output**: The podcast generator uses basic concatenation for large notebooks and returns an MP3. In production, chunked audio stitching should be used for long scripts.
